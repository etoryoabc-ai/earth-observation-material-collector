# v1.1.1 Windows起動修正

## 確認した問題と修正

旧起動.batとv1.1配布ZIP内は日本語を含むUTF-8・LF改行で、両者のバイト列は一致していました。報告された `rvorlevel` 等のエラーそのものは開発Linux環境で再現できていません。文字コード・改行への依存を除去するため、起動.batとテスト.batをASCIIのみ・BOMなし・CRLFへ変更しました。ASCIIの命令部分は日本語WindowsのCP932でも同じバイトで解釈されます。

- バッチ内でのUTF-8コードページ切り替えと日本語メッセージを廃止。複雑な括弧ブロックを使わず、ラベルで分岐。
- Python Launcherの `py.exe -3.12` を検査し、見つからなければPATH上の `python.exe` を検査。どちらも3.12であることを確認してから起動。
- 日本語・空白・&を含むパスを引用符で保護し、遅延変数展開を無効化。pushdでアプリのフォルダに移動。
- Python未検出、ファイル欠落、アプリ例外、アプリ終了時はいずれもpauseを通して画面を保持。
- 日本語案内・例外の表示とログ保存はUTF-8のlauncher.pyへ移動。logs配下へ実行ごとに別名で保存し、既存ログを上書きしない。
- .gitattributesでバッチのバイト列を固定し、生成スクリプトと回帰テストでCRLFを検査。
- 素材検索・採用画面・設定・dataの読み書き仕様は変更していません。

## Windowsで使う手順

1. v1.1.1 ZIPを旧版と別の書き込み可能なフォルダへ「すべて展開」。ZIP内から直接起動しないでください。
2. Python 3.12を導入済みなら、展開先の起動.batをダブルクリック。複雑なコマンド入力は不要です。
3. Pythonがない場合は画面の案内に従い https://www.python.org/downloads/ から3.12をインストールし、Python LauncherまたはPATHオプションを有効にします。
4. 起動に失敗した場合は黒い画面を閉じず、表示内容とlogsフォルダの最新ログを確認してください。バッチの診断文は文字化けを避けるため英語です。Python起動後の詳細案内は日本語です。
5. 既存データを引き継ぐ場合、旧版を終了し、dataフォルダとsettings.local.jsonを新版へコピーします。コピー先に既存データがあれば先にバックアップし、無断で上書きしないでください。APIキーは共有しないでください。
